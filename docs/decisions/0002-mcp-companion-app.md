# 0002 mirage-mcp を画面で扱うアプリ（Mirage MCP）

状態: 決定（2026-10-10 承認）。

## 状況

ADR 0001 で、AI が作品を作って描ける MCP サーバー `mirage-mcp` を作った。コマンドラインのツールなので、次のことに画面がない。

- **登録**：Claude Code や Claude Desktop に登録するには、設定ファイルを書くかコマンドを打つ必要がある。今はプロジェクトに `.mcp.json` を置いている。
- **設定**：Image Importer が読めるフォルダは、起動時の引数 `--allow-images` でしか決められない。
- **様子**：AI がどの道具を呼び、何を作り、どこに保存したかが見えない。
- **止める**：AI の操作を一時的に止める手段がない。
- **置き場所**：登録しているのは `.build/release/mirage-mcp`。ビルドし直すたびに中身が変わり、リポジトリを動かすと動かなくなる。

### 前提として確かめたこと（2026-10-10）

- **MCP サーバーはクライアントが起動する**。stdio の MCP サーバーは、Claude Code などがセッションごとに子プロセスとして起動する。画面のあるアプリそのものを MCP サーバーにはできない（起動のたびにウィンドウが出てしまう）。
- 登録先の設定ファイルは次のとおり（この Mac に両方ある）。
  - Claude Code：`~/.claude.json`（ユーザー全体、プロジェクトごとの設定も含む）、またはプロジェクトの `.mcp.json`。`claude mcp add` コマンドでも登録できるが、この Mac ではターミナルから使える場所に `claude` がない。
  - Claude Desktop：`~/Library/Application Support/Claude/claude_desktop_config.json` の `mcpServers`。
- これらはほかのアプリの設定ファイルなので、書き換えるにはサンドボックスの外で動く必要がある。

## 決定

**画面のある管理アプリ「Mirage MCP」を作り、`mirage-mcp` をその中に同梱する。**

- MCP サーバーの実体は今の `mirage-mcp` のまま。クライアントが起動するのはアプリの中の `Mirage MCP.app/Contents/MacOS/mirage-mcp`。
- アプリは管理役で、`mirage-mcp` とは共有の設定ファイルと記録ファイルでやり取りする。直接の通信はしない。
- App Store には出さず、Developer ID で署名・公証して GitHub のリリースで配る。Mirage Composer 本体と App Store 版には影響しない。

### アプリでできること

| 画面 | 内容 |
| --- | --- |
| **登録** | Claude Code と Claude Desktop への登録・解除と、登録状態（登録済み・パスが古い・未登録）の表示。書き方は下の「登録の方法」のとおり |
| **許可するフォルダ** | Image Importer が読めるフォルダを追加・削除する（今の `--allow-images` の代わり）。フォルダはパネルで選ぶ |
| **AI の操作を止める** | オンの間、`mirage-mcp` は道具の呼び出しをすべて断り、「止められている」と返す |
| **記録** | 道具の呼び出しの一覧（時刻、道具、引数の要約、成功・失敗）。描画した画像の小さな見本と、保存した作品（クリックで Mirage Composer で開く）も出す。「記録を消す」ボタン |
| **状態** | 動いている `mirage-mcp` の数、最後に呼ばれた時刻 |

### やり取りの仕組み

- **設定**：`~/Library/Application Support/Mirage MCP/settings.json`（許可するフォルダ、止めているかどうか）。`mirage-mcp` は道具を呼ばれるたびに読み直すので、アプリで変えるとすぐ効く。
- **記録**：同じフォルダの `activity.jsonl` に、`mirage-mcp` が 1 行ずつ追記する。アプリはファイルの変化を見て表示する。大きくなりすぎないよう、古い分は切り詰める。描画の見本は縮小した画像として別ファイルに残す。
- `--allow-images` は残す（アプリなしで使う人と、テストのため）。設定ファイルの許可と合わせて使う。
- **停止は安全側に倒す**：設定ファイルがないときだけ既定（動く）とし、あるのに読めない・壊れているときは止まっているとみなす。
- **記録は控えめに**：長い値（シェーダーのコード、長い文字列）は要約して残す。各 `mirage-mcp` は 1 行を 1 回の追記で書き、切り詰めや削除はアプリだけが行う。件数と容量（見本の画像を含む）に上限を設け、古いものから消す。

### 登録の方法

- **Claude Code：`~/.claude.json` は直接書き換えない**。このファイルにはプロジェクトの情報や、ほかの MCP サーバーの設定（API キーを含むことがある）が入っていて、Claude Code 自身も頻繁に書き込む。同時に書くと変更が消えたり壊れたりする恐れがあり、控えにも秘密の情報が複製される。代わりに、公式の登録コマンド（`claude mcp add --scope user mirage -- <パス>`、解除は `claude mcp remove`）が見つかればそれを実行し、見つからなければそのコマンドを表示してコピーできるようにする。
- **Claude Desktop：設定ファイルを書き換える**。`claude_desktop_config.json` の `mcpServers` の `mirage` だけを変え、ほかには触れない。書く直前に読み直して一度で書き換える。書き換える前の控えは自分だけが読める権限（0600）で、数を限って残す。反映には Claude Desktop の再起動が要ることを表示する。

## 進め方

1. **共有の設定と記録**：`mirage-mcp` が設定ファイル（許可するフォルダ、停止）を読み、記録を書くようにする。テストを足す。
2. **アプリの骨組み**：SwiftUI の小さなアプリ。許可するフォルダ、停止、記録の画面。`bundle` スクリプトで `mirage-mcp` を同梱する。
3. **登録**：Claude Code と Claude Desktop への登録・解除。変更内容の確認と控え。
4. **配布**：署名・公証して GitHub のリリースに置く。README に使い方を書く。

## 影響

- パッケージに、管理アプリの実行ファイルが 1 つ増える。Mirage Composer 本体、App Store 版、OnomFlow には影響しない。
- 今の `.mcp.json`（ビルドの場所を指す）は、アプリからの登録に置き換える。
- Claude Desktop の設定ファイルを書き換える。決まった項目（`mcpServers` の `mirage`）だけを変え、ほかには触れない。書き換える前に控えを残し、変更内容を見せてから書く。Claude Code の設定は公式のコマンドに任せる。
- Claude Code や Claude Desktop の設定の形式が変わると、登録の部分が動かなくなる恐れがある。Claude Code は公式のコマンドを使うので影響は小さい。
- 配布物が Mirage Composer とは別に 1 つ増え、リリースの作業が少し増える。

## 未確認

- Claude Desktop と Claude Code で、MCP サーバーの起動の仕方（作業フォルダ、環境変数）の違い。
- 記録に引数をどこまで残すか（作品のパスや文字列は残してよいが、長い値は要約する）。
