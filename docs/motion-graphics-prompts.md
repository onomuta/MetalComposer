# モーショングラフィックスを頼むときのプロンプト集

mirage-mcp に新しい作品を作らせるときのテンプレート。型（A〜D）を 1 つ選んで `［ ］` を埋め、その後ろに **共通ブロック** を貼って使う。共通のルールは共通ブロックにだけ書き、型には書かない。

普段は **A**、方向性を探りたいときは **B** で数を出す。

## 共通ブロック（どの型にも付ける）

```
【共通ルール】

■ 位置づけ
AIエージェントによる映像制作から体験型Webサイトの制作まで、どこまで表現できるかを確かめる実験でもある。
表現は過剰でもいい。思いきり創造性を発揮する。アイデアはあくまでヒントで、そのとおりに再現しなくていい。

■ 品質
優秀なモーショングラフィックデザイナーが全力で作ったリールムービーの水準を目指す。
- どのフレームで止めても、ポスターとして成り立つ構図と配色にする。
- 最初の1秒でつかむ。出だしから見せ場を置く。
- 速いところと溜めるところの緩急をはっきりさせる。全部が同じ速さで動かない。
- 主役の動きに、遅れてついてくる動き（追従・重なり・余韻）を添える。
- シーンのつなぎも見せ場として設計する。ただのカットで済ませない。
- 描画して確かめ、「これで十分」ではなく「まだ良くできるところ」を探して直す。

■ パッチ設計
表現したい視覚現象を先に決め、それに合うパッチを選ぶ。
- 形と配置：Billboard・Sprite・Cube・Sphere など
- 反復と分布：Iterator・Particle System など
- 時間変化とタイミング：Interpolation・LFO・Random・Smooth・Math Expression など
- 変換と運動：3D Transformation など
- 文字：Text Image・Text Characters
- 履歴とデータ：Queue・Structure 系
- 合成：Render In Image
- 色：HSL Color・Multiplexer など
- 外部入力：ONOM FLOW Input（下記）
これらは選択肢で、すべてを使う必要はない。各パッチに明確な役割を持たせ、目的のない複雑化を避ける。
Metal Shader 1つで全部を描くことはしない。
- Metal Shaderは、パッチの組み合わせでは作りにくい模様・質感・テクスチャに使う。重くならないよう、
  画面全体を毎フレーム計算する複雑なシェーダーは避け、Render In Imageの中で小さな画像に描いて使い回す。
- 必要な画像素材（ロゴ、図形、テクスチャ、文字組みなど）はJavaScriptなどで別に作ってPNGにし、
  Image Importerで読み込む。画像は作品と同じフォルダか、読み込みを許可したフォルダに置く。
- フィードバック（Render In Imageの自己ループ）やBloomに頼りすぎない。画面がぼやけてVJで使いづらくなる。
  形はくっきり、コントラストは高く保ち、使うなら小さなアクセントに留める。
技術的な制約で実現できない表現があれば、別の構成を検討する。

■ ONOM FLOW Input
作品はVJアプリONOM FLOWで素材として流すことがある。効くところでは小さく効果的に使い、無理には使わない。
- BPM・Beat：拍に合わせる動きはBeat（拍の中の位置 0〜1）を使う。ONOM FLOWのテンポに追従し、単体でもBPM（既定120）で進む。
  拍の回数が要るときはMath Expression 1つで floor(t * BPM / 60 - Beat + 0.5) + Beat とする（整数部が拍の回数、小数部がBeat）。
  CounterでBeatの折り返しを数える方法は、フレームが落ちると拍を取りこぼすので使わない。
- Main Color・Sub Color：主役の色とアクセント色。VJがその場で配色を変えられる。既定はどちらも白なので、
  同じ色でも成り立つ作りにする（黒い縁取りや明暗差で区別するなど）。
- Input 1〜4：VJが回すつまみ（0〜1）。密度・速さ・ねじれなど、作品の性格を変える量を1〜2個だけ割り当てる。
- Text 1〜2・Image 1〜2：名前やロゴを差し込む素材のときに使う。
- Gain：Audio Inputなどマイク入力の値に掛ける倍率（現場でマイクのレベルを合わせるつまみ）。音の大きさそのものではないので、
  形や動きに直接つながない。マイク入力を使わない作品では使わない（mirage-mcpではマイクのパッチを追加できない）。
- パッチはマクロやIteratorの中にも置ける。中で値が要るなら、外から配線せずにその中に置く。

■ 完成の条件
見た目だけでなく、実際に動作する作品として完成させる。
- 複数の時刻を描画して確かめる（拍の頭・途中・切り替わり・ループのつなぎ目）。
- フレームが落ちても破綻しない（拍の回数は式で数える）。
- ONOM FLOWの既定値（色は白×白、Textは「Text 1」）や、長さの違う文字でも成り立つ。
- 重い処理を避け、VJで長時間流しても安定する。
保存したら、構成と調整ポイントを短く説明する。足りない機能や不具合に当たったら、作品を仕上げたあとにまとめて報告する。
```

## A. 詳細ブリーフ型（品質がいちばん安定する）

```
Mirage Composerで新しいモーショングラフィックスを作って、［保存先］.mcompに保存して。

■ コンセプト：［一言で。例：呼吸するタイル／重力で落ちる図形］
■ 雰囲気：［形容詞を3つ。例：ポップ・シンプル・モダン］
■ 尺とテンポ：［BPM○○で1小節ごとに展開／BPMなし・○秒でループ］
■ 構成：［例：4シーン×1小節、最後のシーンが最初につながってループ］
■ 配色：背景［黒］、色は［○色まで。例：ピンク・イエロー・シアン・白］
■ 動きのルール：
  - イージング：［例：expo-outで止まる瞬間にキレ、back-outで弾む］
  - 時間差：［例：要素ごとに少しずつずらす］
  - 余白：［例：画面の○割は空ける／画面を埋め尽くす］
■ 主役のパッチ：［例：Iterator／Particle System／Text Characters／おまかせ］
■ 文字：［なし／小さいラベルのみ／タイトルを大きく］
■ NG：［例：グラデーション多用、文字だらけ］
```

## B. ミニマル型（試作を早く回す）

```
［コンセプト］のモーショングラフィックスを作って。
［BPM○○／自由テンポ］、背景［黒］、［ポップ／静か／クール］な感じ。
主役のパッチは［Iterator／Particle System／おまかせ］。［保存先］に保存。
```

決まっていない部分は AI が判断するので、毎回違う方向性が出る。数を出して選ぶのに向く。

## C. リファレンス・ムード型（作風を寄せる）

```
次のような作風で、新しいモーショングラフィックスを作って。

■ 参考にしたい作風：［例：スイスデザインのポスターが動く感じ／
  Apple製品紹介のミニマルさ／90年代のメンフィス柄］
■ 寄せたい点：［例：太い幾何学形、大胆な余白、限られた色数］
■ 寄せなくていい点：［例：写真やロゴは使わない］
■ 見る人に感じてほしいこと：［例：気持ちいいリズム感／ずっと見ていられる］
■ 条件：［BPM・尺・背景・保存先］

まず作風の解釈を3行で書いてから作り始めて。
```

最初に解釈を書かせるので、作る前に方向のずれに気づける。

## D. 技法チャレンジ型（Mirage の機能を掘る）

```
［機能名：Iterator／Render In Image／Particle System／Queue／Text Characters など］
を主役にしたモーショングラフィックスを作って。

■ その機能でしかできない見せ方を1つ核にする：［例：何百個もの要素の群れ、
  値の履歴で描く軌跡、奥行きのあるカメラワーク］
■ 動きの性格：［規則的／ランダムで有機的／その中間］
■ 条件：［BPM・尺・背景・配色・保存先］
```

作品づくりと mirage-mcp のテストを兼ねる。Multiplexer の設定の不具合（e698ea2 で修正）や、Text Characters パッチの追加も、この種の作業から生まれた。

## どの型にも足せる一文

- 「〇秒・〇秒・〇秒の静止画で確認してから保存して」：見せ場のタイミングを指定できる。
- 「2案作って比べさせて」：方向性で迷っているときに。
