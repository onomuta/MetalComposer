# モーショングラフィックスを頼むときのプロンプト集

mirage-mcp に新しい作品を作らせるときのテンプレート。`［ ］` を埋めて使う。どれも、テンポと尺・色の数・動きのルール・技法・仕上がりの確かめ方を項目にしてある。

普段は **A**、方向性を探りたいときは **B** で数を出す。

## どの型にも共通のルール

### この制作の位置づけ

AI エージェントによる映像制作から体験型 Web サイトの制作まで、どこまで表現できるのかを確かめる実験でもある。

- 表現は過剰でもいい。思いきり創造性を発揮する。
- テンプレートに書いたアイデアはあくまでヒント。そのとおりに再現しなくていい。

### 品質の目標

優秀なモーショングラフィックデザイナーが全力で作ったリールムービーの水準を目指す。リールは、選び抜いた見せ場だけをつないで腕前を示す作品集。そのつもりで、次のことを詰める。

- どのフレームで止めても、ポスターとして成り立つ構図と配色にする。
- 最初の1秒でつかむ。出だしから見せ場を置く。
- 速いところと溜めるところの緩急をはっきりさせる。全部が同じ速さで動かない。
- 主役の動きに、遅れてついてくる動き（追従・重なり・余韻）を添える。
- シーンのつなぎも見せ場として設計する。ただのカットで済ませない。
- 描画して確かめ、「これで十分」ではなく「まだ良くできるところ」を探して直す。

### 技法

Metal Shader 1つで全部を描かない。Mirage のパッチを組み合わせて作る。

- 形は Billboard・Sprite・Cube・Sphere・Particle System などで置き、Iterator で並べる。
- 動きは Interpolation・LFO・Random・Math Expression・Smooth でつける。
- まとめて動かすのは 3D Transformation、重ねや残像は Render In Image、色は HSL Color や Multiplexer で切り替える。
- Metal Shader は、パッチでは作れない部分（背景の模様、タイル画像、特殊な効果など）だけに使う。
- フィードバック（Render In Image の自己ループ）や Bloom に頼りすぎない。画面がぼやけて VJ で使いづらくなる。形はくっきり、コントラストは高く保ち、使うなら小さなアクセントに留める。

### ONOM FLOW Input

作品は VJ アプリ ONOM FLOW で素材として流すことがある。ONOM FLOW Input パッチを使うと、ONOM FLOW から渡される値で作品を動かせる。無理に使わなくていいが、効くところでは小さく効果的に使う。

- **BPM・Beat**：拍に合わせる動きは、`t` から自前で拍を計算する代わりに Beat（拍の位置 0〜1）を使う。ONOM FLOW のテンポに追従し、単体で再生しても BPM（既定 120）で進む。Beat は拍の中の位置だけなので、拍の回数が要るときは Math Expression 1 つで `floor(t * BPM / 60 - Beat + 0.5) + Beat`（整数部が拍の回数、小数部が Beat）とする。Counter で Beat の折り返しを数える方法は、フレームが落ちると拍を取りこぼすので使わない。
- **Main Color・Sub Color**：主役の色とアクセント色に使うと、VJ がその場で配色を変えられる。既定はどちらも白なので、同じ色でも成り立つ作りにする（黒い縁取りや明暗差で区別するなど）。
- **Gain**：Audio Input・Audio Spectrum など、マイク入力の値に掛ける倍率。現場でマイクのレベルを手早く合わせるためのつまみなので、音に反応させるときは入力の値 × Gain で使う。音の大きさそのものではないので、形や動きに直接つながない。マイク入力を使わない作品では使わない（mirage-mcp ではマイクのパッチを追加できない）。
- **Input 1〜4**：VJ が回すつまみ（0〜1）。密度・速さ・ねじれなど、作品の性格を変える量を1〜2個だけ割り当てる。
- **Text 1〜2・Image 1〜2**：名前やロゴを差し込む素材のときに使う。
- パッチは作品のどこに置いてもよく、マクロや Iterator の中にも置ける。中で値が要るなら、外から配線せずにその中に置く。

各テンプレートには、この制作の位置づけ・品質の目標・技法のルール・ONOM FLOW Input をそれぞれ一文で入れてある。

## D. 技法チャレンジ型（Mirage の機能を掘る）

```
［機能名：Iterator／Render In Image／Particle System／Queue／3D Transformation など］
を主役にしたモーショングラフィックスを作って。

■ その機能でしかできない見せ方を1つ核にする：［例：フィードバックの残像、
  何百個もの要素の群れ、奥行きのあるカメラワーク］
■ 動きの性格：［規則的／ランダムで有機的／その中間］
■ 条件：［BPM・尺・背景・配色・保存先］
■ 技法：主役の機能のまわりも、Metal Shaderに頼らずパッチで組む。
■ ONOM FLOW：ONOM FLOW Inputが効くところでは使う（拍はBeat、色はMain／Sub Color、つまみはInput 1〜4。Gainはマイク入力に掛ける倍率）。無理に使わなくていい。
■ 品質：優秀なモーショングラフィックデザイナーが全力で作ったリールムービーのクオリティ。
■ 自由度：AIエージェントの表現の限界を試す実験でもある。表現は過剰でもOK、思いきり創造性を発揮して。アイデアはヒントで、再現しなくていい。

使えない機能やMCPの不具合を見つけたら、作品を作り終えたあとにまとめて報告して。
```

作品づくりと mirage-mcp のテストを兼ねる。Multiplexer の設定の不具合（e698ea2 で修正）も、この種の作業で見つかった。

## どの型にも足せる一文

- 「動きは"溜め→動く→止まる"のメリハリを意識して」：のっぺりした動きを防ぐ。
- 「要素は少なく、1つ1つの動きを丁寧に」：詰め込みすぎを防ぐ。
- 「〇秒・〇秒・〇秒の静止画で確認してから保存して」：見せ場のタイミングを指定できる。
- 「2案作って比べさせて」：方向性で迷っているときに。
